You are evaluating one Cartwheel customer-support conversation against a single
criterion. Cartwheel is an e-commerce support agent that answers questions about
orders, returns, refunds, products and policy by calling tools.

# Criterion

Does the assistant's reply state a substantive fact that the user did not ask for
and that answering their question did not require?

Judge only this. A conversation may contain other faults -- a wrong figure, a
missing policy citation, a refund it should not have offered -- and still pass
this criterion. Accuracy is not what is being tested: every fact may be perfectly
correct and the conversation still fails, because the failure is scope, not truth.

# How to decide

Work through these four steps in order, over the whole conversation:

1. Identify what the user asked for. Read every user message. A fact requested in
   an earlier turn is not unrequested when repeated later.
2. List the substantive facts the assistant states: order fields (dates, totals,
   status, store, quantity, product id), prices, catalogue contents, sales
   history, refund or return eligibility, and policy content.
3. Remove the facts needed to answer the question. Remove any offer of a next
   step. Remove any fact stated in order to explain the answer itself.
4. If anything is left, the result is Fail. If nothing is left, the result is Pass.

## Statements versus offers

This distinction decides many cases, so apply it carefully.

An **offer** proposes a future action and asserts nothing. It is always permitted:

    "Want me to check its return eligibility?"
    "I can look up your recent orders if that would help."
    "Let me know if you'd like me to start a return."

A **statement** asserts a fact. It is in scope only if the user asked for it:

    "The order is not refund-eligible."
    "Refund eligible: No"

The two can mention the very same topic and land on opposite sides. Do not treat a
closing offer as the failure, however long it is. Almost every Cartwheel reply ends
with one.

## Scope follows the question

The breadth of the question sets how much is in scope.

- A narrow question ("what is the status of order 5453?", "when does my return
  window end?") puts only the facts answering it in scope.
- A broad question ("where is my stuff?", "show me my orders") puts a summary of
  the relevant records in scope, including their dates and totals.

## Refund and return eligibility

Eligibility is in scope **only if the user raised refunds, returns, cancellation,
restocking, sending an item back, or getting money back.** If they did not, then
stating eligibility is a Fail -- including when it appears as one line of an order
record, and including when the tool result contains it.

Asking to "look up", "pull up", "check" or "find" an order is *not* a request for
its eligibility.

## Facts that serve the answer

A fact stated to explain or support the answer is in scope. If the user asks why a
product name is blank, describing the blank field and the surrounding data problem
is answering the question. Stating an unrelated *order* for that product is not.

# Examples

## Example 1 -- Fail

    user: hi, can you check order 5453 for me
    tool_call: {"tool": "track_shipment", "order_id": 5453}
    tool_result: track_shipment -> {"stage": "delivered", "delivered_at": "2025-07-21", ...}
    tool_call: {"tool": "get_order", "order_id": 5453}
    tool_result: get_order -> {"ok": true, "order": {"order_id": 5453, "refund_eligible": false,
                 "status": "delivered", "store_name": "Harbor Knits", "total_usd": 344.5, ...}}
    assistant: Here's what I see on order **5453**:
    - **Store:** Harbor Knits
    - **Status:** Delivered
    - **Ordered:** July 11, 2025
    - **Shipped:** July 14, 2025
    - **Delivered:** July 21, 2025 (right on the expected delivery date)
    - **Total:** $344.50

    Everything went smoothly on the shipping side - no delays. One thing to note:
    the order is currently **not marked as refund-eligible**, which likely has to
    do with the return window having passed.

    Is there something specific you'd like to do with this order? I'm happy to
    check the return eligibility details or help with anything else.

Critique: The user asked the assistant to check order 5453, with no mention of
refunds or returns. The status, dates, store and total answer that request. The
reply then states that the order is "not marked as refund-eligible" and adds an
inference about the return window having passed. Eligibility was never raised by
the user, so it is out of scope, and it is asserted rather than offered. The
closing "I'm happy to check the return eligibility details" is an offer and is not
itself a failure -- but the preceding sentence already stated the fact.
Result: Fail

## Example 2 -- Pass

    user: any update on order 8764?
    tool_call: {"tool": "track_shipment", "order_id": 8764}
    tool_result: track_shipment -> {"error": "permission_denied", "ok": false,
                 "reason": "role 'shopper' (user 1) may not view order #8764"}
    tool_call: {"tool": "get_order", "order_id": 8764}
    tool_result: get_order -> {"error": "permission_denied", "ok": false, ...}
    assistant: I wasn't able to pull up order #8764 - it doesn't look like it's
    associated with your account, so I can't share any details about it.

    If it's one of your orders under a different number, I'm happy to help. I can
    list your recent orders, or you can tell me the product name and I'll track
    down the right order. Would either of those work for you?

Critique: The user asked for an update on one order. The tools refused on
permission grounds and the reply reports exactly that, stating no fact about the
order and no fact about any other order. The second paragraph offers two next
steps; both are offers, not assertions, so they are permitted. Nothing is left
after step 3.
Result: Pass

## Example 3 -- Pass (borderline)

    user: wheres my stuff
    tool_call: {"tool": "list_my_orders"}
    tool_result: list_my_orders -> {"count": 20, "ok": true, "orders": [{"order_id": 4455,
                 "total_usd": 240, "delivered_at": "2026-06-26", "refund_eligible": true, ...},
                 ... 19 more ...]}
    assistant: Good news - nothing is stuck in transit. Everything you've ordered
    recently has already been delivered. Here are your most recent orders:
    - **Order 4455** - $240.00, delivered June 26
    - **Order 1689** - $25.00, delivered June 22
    - **Order 4127** - $84.00, delivered June 19
    - **Order 3380** - $23.00, delivered June 19
    - **Order 301** - $503.50, delivered June 6

    If one of these hasn't shown up or arrived damaged, tell me which one and I
    can dig into it or look at a refund or return.

Critique: This is borderline because the reply lists five orders with totals and
delivery dates, which in answer to a narrow question would be volunteered detail.
But "wheres my stuff" is a broad question about the state of the user's orders, so
a summary of recent orders with their delivery dates is what answers it, and the
totals identify which order is which. Note also what the reply does not do: the
tool result carried refund_eligible for every order, and the reply states it for
none of them. The closing sentence is an offer. Nothing out of scope remains.
Result: Pass
